# inkMOD — список изменений

Сводка всех правок, сделанных за это время. Сгруппировано по темам, не по хронологии.

## FB2 — движок парсинга переписан с нуля

Это была не точечная правка, а полная замена движка разбора FB2:

- **Убран expat** (сторонняя библиотека XML-парсинга, ранее — 1233 строки `Fb2.cpp` на её основе) — вместо него написан **свой, зависимостей не требующий потоковый парсер** (`Fb2XmlReader`, ~250 строк): без построения DOM-дерева в памяти, без единого выделения памяти больше размера одного маленького буфера — критично для 380КБ доступной RAM на ESP32-C3.
- Вместе с этим написан **свой ZIP+DEFLATE слой** (`Inflate.h/.cpp`, `ZipReader.h/.cpp`) для распаковки `.fb2.zip` — тоже без сторонних библиотек, проверен на реальных архивах, собранных стандартным `zip`.
- **Изменилась сама модель книги**: раньше был единый двухпроходный expat-парсер с ручным отслеживанием глубины тегов и склейкой глав по границам абзацев. Теперь — `scan()` (разовое индексирование: список секций с уровнем вложенности и позициями в файле) и `renderSection()` (рендер ОДНОЙ секции по требованию, без разбора всего файла). Каждая `<section>` FB2, на любом уровне вложенности, становится отдельной главой — что уже само по себе и есть основа ленивой подгрузки, о которой шла речь ниже.
- **Новые возможности, которых не было в старом парсере**:
  - Настоящие таблицы (`<table>/<tr>/<td>/<th>` с `colspan`/`rowspan`/`align`), раньше схлопывались в обычные абзацы.
  - Small-caps через именованный `<style name="...">` (распознаёт `smallcaps`, `small-caps`, `sc` и похожие варианты).
  - Корректное декодирование именованных HTML-сущностей (`&mdash;`, `&laquo;`, `&hellip;` и т.д.), не только 5 базовых XML-сущностей.
  - **Мягкий перенос** (`&shy;`) и **неразрывный пробел** (`&nbsp;`) теперь сохраняются как настоящие юникод-символы (раньше `&shy;` тихо терялся) — это то, что потом даёт правильные точки переноса слов на уровне вёрстки.
  - Встроенная в книгу CSS-таблица стилей (`<stylesheet>`) теперь извлекается, включая варианты в `CDATA`.
- Публичный API класса `Fb2` (`load()`, `getTitle()`, `getChapterCount()` и т.д.) сохранён без изменений — вызывающий код (`FileBrowserActivity` и другие) трогать не пришлось.

Дальше, уже в рамках этой части разговора, эта архитектура получила: ленивую подгрузку глав/картинок «по требованию», разбиение перегруженных картинками секций, рабочие сноски, фикс детекта ZIP-архивов и защиту от зависания на битом контенте — всё это описано ниже, но фундаментом для всего было именно это.

## FB2 (последующие правки поверх нового движка)
- **Разбиение перегруженных картинками секций** на несколько виртуальных глав (например, 23 картинки в одной секции → 4 главы по 6+6+6+2), чтобы не упираться в лимиты памяти при рендере.
- **Рабочие сноски** (`<a l:href="#n1">`) — переход на конкретный якорь, а не всегда в начало книги.
- **Критический фикс детекта ZIP-архивов**: раньше распознавались только файлы вида `*.fb2.zip` (с точкой); файлы с другим разделителем (например, `_fb2.zip`) не распознавались как архив, парсер пытался читать сжатые байты как текст — отсюда крах при индексации. Детект расширен на любые `*.zip`.
- **Защита парсера от зависания/краха** на повреждённом или нестандартном контенте (цикл чтения атрибутов тега теперь корректно завершается, если нет прогресса, вместо бесконечного цикла или переполнения памяти).

## EPUB

- **Фикс сносок**: убрано ошибочное исключение `<span id="...">` из карты якорей — раньше такие сноски всегда открывали первую попавшуюся, а не нужную.
- **Препроцессор для книг с гигантскими главами** (весь сборник рассказов в одном HTML-файле на несколько мегабайт) — на устройстве такая глава либо зависала на минуты, либо падала по памяти.
  - Сначала пытался чинить прямо на устройстве — там же обнаружился баг с распаковкой больших файлов, который не удалось надёжно починить в существующих условиях памяти устройства.
  - **Финальное решение**: разбиение вынесено на этап **веб-загрузки** (в браузере, где памяти с избытком) — при включённой оптимизации слишком большие главы режутся на части по безопасным границам HTML-тегов, оглавление и все перекрёстные ссылки автоматически переписываются на нужные части. Проверено на реальной книге («Полное собрание рассказов» Набокова) — все 74 ссылки оглавления корректно ведут на свои части.
- **Тройная защита от зависания на больших главах** (открытие книги, фоновая предзагрузка следующей главы, генерация превью для экрана сна) — раньше защита стояла только в одном из трёх мест.
- **Small-caps** (`font-variant: small-caps`) — распознаётся из CSS (включая классы), рендерится уменьшенным масштабом текста (без замены регистра букв — это было бы риском для кириллицы на низком уровне парсера текста).

## Типографика (общая, для FB2 и EPUB)

- **Исправлена неравномерная выключка по ширине (justify)**: при малом числе слов в строке весь излишек пространства раньше уходил в 1-2 промежутка целиком, из-за чего рядом с короткими предлогами («и», «с», «в») visuально образовывались неоправданно большие разрывы. Теперь растяжение одного промежутка ограничено ~2x от его естественной ширины; если этого не хватает — строка просто не дотягивается до полного края, а не тянется «через силу».

## Настройки

- **«Внутренняя память»**: раньше расчёт запускался автоматически при входе в меню и мог подвесить экран на несколько секунд/минут при большой карте. Теперь расчёт запускается только по нажатию «Выбрать», и экран сам обновляется, когда расчёт готов (раньше приходилось тыкать ещё раз).
- **«С последней зарядки»**: добавлен показатель. Несколько итераций по надёжности:
  - Изначально хранился только в RTC-памяти — обнулялся при каждой перепрошивке.
  - Добавлено сохранение на карту, чтобы переживать перепрошивку/сброс.
  - Обнаружено и исправлено: устройство на батарее при глубоком сне **полностью обесточивается** (включая RTC-память) — значение нужно сохранять на карту сразу в момент отключения зарядки, а не по таймеру.
  - Добавлен более частый и надёжный опрос состояния зарядки (раньше зависел от того, когда что-то ещё спрашивало заряд батареи).
- Попап «Загрузка» при подсчёте памяти заменён на понятную подсказку «Нажмите «Выбрать»».
- **Переключатель «Часы (X4)» ВКЛ/ВЫКЛ** — были перепутаны местами (показывало обратное).
- **Язык** — строка настройки теперь показывает текущий выбранный язык.
- **Перевод**: исправлено «Russian» вместо «Русский» в списке языков (опечатка в исходном файле перевода), исправлены захардкоженные английские обозначения времени («1h 20m») в превью настроек строки состояния.
- **Счётчик страниц в строке состояния**: добавлен третий режим — «по книге» (оценка, основанная на байтовом соотношении текущей главы и всей книги) в дополнение к «по главе».

## Календарь на экране сна (новая функция)

Добавлены два новых режима сна: **«Календарь (альбомный)»** и **«Календарь (альбомный, инверсия)»** — по аналогии с уже существующими портретными.

Потребовалось несколько итераций по фото с реального устройства:
- Раскладка под альбомную ориентацию (боковая колонка с месяцем/годом/крупными цифрами/лого + сетка дней).
- Направление поворота экрана (несколько попыток, включая правки с учётом того, как устройство стоит в чехле на столе).
- Отрисовка логотипа: обнаружен и обойдён «TODO: Rotate bits» — недоделка в самом движке отрисовки картинок (не поворачивает пиксели при повороте экрана, хотя текст поворачивает корректно). В итоге логотип рисуется через тот же примитив, что и остальные элементы экрана (гарантированно повторяет правильный поворот).
- Направление поворота логотипа (90° по часовой) и полярность битов картинки (0 = чёрный, была перепутана — отсюда «чёрный квадрат» на одной из итераций).
- Симметрия: выравнивание боковой колонки и сетки дней по общей верхней точке (вместо независимого центрирования каждого блока), ширина колонки подогнана под ширину логотипа, текст «inkmod» центрирован под иконкой.

## Веб-загрузка (files.js)

- **Обложки**: фикс оптимизатора — раньше маленькие обложки не увеличивались до размера экрана (только уменьшались), теперь масштабируются в обе стороны.
- **Разбиение перегруженных EPUB-глав** при загрузке — см. раздел EPUB выше.

## Разное

- **Пустой экран в карусели на главном экране** при возврате из меню/проводника — не сбрасывался сохранённый снимок обложки.
- Проверена и подтверждена **точность гифенации** (переноса слов) для русского языка через собранный тестовый стенд, сверенный с исходным тестовым набором проекта — 97.22%, выше порога в 96.22%, который сами разработчики считают приемлемым (не баг, статистическое ограничение любого алгоритма такого типа).

## Не поддерживается по железу

- **USB как флешка (MSC)** — физически невозможно на используемом чипе ESP32-C3: его USB-контроллер жёстко зашит в кремний только под последовательный порт и JTAG-отладку, перепрограммировать это нельзя. Для этого нужен другой чип (ESP32-S2/S3).
